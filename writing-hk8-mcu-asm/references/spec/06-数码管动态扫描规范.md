# 06 数码管动态扫描规范

## 1. 适用范围与板级输入

本文只定义 HK64S825 驱动数码管时的通用生成规则，不包含任何开发板接线答案。不得从本文、旧任务或已注册 profile 推断当前用户的 GPIO。

创建候选 ASM 前必须由用户直接提供，或明确选择已注册 board profile 后解析：

- 驱动方式：GPIO 直驱、移位寄存器或专用驱动芯片；
- 位数、数码管/模块型号和每位共阳或共阴类型；
- A、B、C、D、E、F、G、DP 的逐段映射；
- 从左到右每一位的 COM 映射、选通电平和关闭电平；
- 外部三极管/MOS/驱动芯片造成的逻辑反相；
- OSC、SCK_PS、目标刷新率或允许采用的近似刷新范围；
- GPIO ownership、共享关系、限流电阻和驱动能力约束。

缺少任一会改变 GPIO 写法、电气安全、段码、位序或时序的值时，必须停在候选生成之前。适用规则：`HK-7SEG-001..007`。

## 2. 初始化

段线和位选都固定遵循：目标 `POD` -> 安全 `PIO` -> 最后开启 `POE`。以下名称只是经 board contract 解析后的角色占位符，不是 HK64S825 SFR：

```text
SEG_POD -> SEG_PIO -> SEG_POE
DIGIT_POD -> DIGIT_PIO -> DIGIT_POE
```

先按逐引脚 drive contract 建立推挽或开漏模式，再预装“所有位关闭且段线安全”的锁存值，最后打开输出使能。只有 PinContract 明确拥有整口时才允许整口写入；否则必须 read-modify-write 保留非本任务位。不得依赖复位值，不得先开 `POE` 再补写安全状态。

### 2.1 端口独占整字节写

当 board contract 明确 PB7..PB0 全部仅用于当前数码管段线时，固定段线值和查表得到的动态段码均优先整字节写入。不得将等价的整口固定值展开为八条逐 bit 指令。

    ; 段线安全状态为低电平时
    MOV A,#00H
    MOV PB_PIO,A

    ; A 已为当前物理段码时
    MOV PB_PIO,A

00H 与 0FFH 的安全性取决于段线有效电平和当时所有位选是否已关闭；不得把它们互换。端口任一 bit 被其他模块共享、所有权未确认，或存在位选未关闭时，必须使用所有权保留的 RMW 或逐 bit 写法。

### 2.2 已验证驱动保持

用户提供且确认正常的数码管计时器、查表和扫描顺序是该板的实板证据。业务层修改时保持其 Timer0 模式、溢出参数、flag 清除位置、查表顺序和位选顺序；不得把已验证的轮询驱动擅自改成中断驱动。替换驱动方式前，必须逐项完成 Timer0 时基、向量、总中断和显示亮度的实板 probe。

## 3. 段码生成

先用逻辑段集合表示数字，例如数字 1 使用 B、C，数字 2 使用 A、B、D、E、G。然后根据用户确认的 A-G/DP bit mapping、段线有效电平和外部反相生成物理段码。

不得内置“某端口 bit7 到 bit0 恰好对应 A 到 DP”的假设。共阳/共阴只是器件拓扑线索；如果外部驱动发生反相，以 MCU 引脚实际有效电平为准。DP 必须单独记录关闭和点亮电平。

## 4. 视觉位序

业务显示数组按视觉从左到右保存。board contract 必须明确每个视觉索引对应哪个位选信号，不得根据 COM 编号猜物理位置。

发现数字循环移位或左右顺序错误时，先核对视觉索引到位选的映射，不要交换业务数据来掩盖接线错误。

## 5. 无鬼影扫描序列

GPIO 动态扫描时，每一位严格执行：

```text
全部位选关闭
-> 写入当前位段码
-> 只打开当前位选
-> 保持短延时
-> 全部位选关闭
```

禁止在任意位选打开时切换段线。若段线和位选经外部器件反相，“全部关闭”和“只打开当前位”的实际电平必须由 board contract 计算，不能使用固定字面量。

## 6. 驱动方式分支

- GPIO 直驱：使用 PinContract 和上述无鬼影扫描序列。
- 移位寄存器：确认器件型号、数据/时钟/锁存引脚、移位方向、输出有效电平和级联长度。
- 专用驱动芯片：确认型号、总线类型、地址、亮度/扫描寄存器和字节顺序，优先按器件数据手册实现。

驱动方式未知时不得选择 GPIO 直驱作为默认答案。

## 7. 状态与 scratch 分离

每个视觉位的业务值属于 persistent display state；扫描索引、段码转换输入和延时计数属于 scratch。具体 SRAM 地址按当前项目内存分配确定，不得复用同一地址承担长期状态和 scratch。

## 8. 段码转换与比较

如果使用 `SE` 链转换数字，先保存原始数字，每次比较前重载 A。连续比较不得依赖前一次 `SE` 后的 A 状态。段码表或分支的输出必须继续经过当前 board contract 的极性和 bit mapping 变换。

## 9. BCD 计数

多位十进制状态应逐位独立进位。计数更新发生在完整 frame 之间；若由 ISR 更新，使用双缓冲、原子快照或等价保护，避免一次 frame 混用两个时刻的数据。

溢出后回到零还是其他起始值属于功能事实，必须由用户需求确定。

## 10. 刷新率和亮度

对 N 位动态扫描：

```text
frame_rate = digit_refresh_rate / N
```

精确延时必须从用户提供或确认 profile 中的 OSC、SCK_PS 和实际 SCK 推导，并通过 cycle audit。不得跨 board profile 照抄延时常量。峰值段电流、平均占空比和限流设计必须符合已确认的硬件约束。

## 11. 诊断矩阵

| 症状 | 优先检查 |
|---|---|
| 上电多位同时亮 | 全关电平、外部反相、初始化顺序 |
| 串影 | 写段码前是否全关、dead-time |
| 数字顺序错 | 视觉索引到位选映射 |
| 某些位反相或乱码 | 每位拓扑、段有效电平、外部驱动反相 |
| 亮度不均 | 每位路径 cycles、占空比、驱动能力 |
| 只显示一位 | 其他位选的 POE/PIO 和扫描回路 |

诊断不得以加载其他开发板 profile 作为捷径。

## 12. 最小实板验证顺序（仅后续硬件阶段）

本节只在用户明确要求硬件验收时执行：

1. 所有位选关闭，确认无段点亮。
2. 固定安全段图，逐个打开位选，记录物理顺序和实际有效电平。
3. 逐个测试 A-G、DP，确认映射和反相。
4. 显示不对称的四个不同数字，确认视觉位序。
5. 覆盖全部数字和 DP，确认段码。
6. 测量 frame period、每位 on-time、dead-time 和电流。

探测结果必须由用户确认后写入新的 board profile，不能只保存在模型推断中。

## 13. 交付清单

### 普通编译 release（必需）

- [ ] `input_provenance.board/pins/clock` 来自用户提供或用户明确确认的 profile。
- [ ] board contract 含驱动方式、段线、位选、极性、物理位序、反相、DP 和限流信息。
- [ ] 初始化按目标 `POD` -> 安全 `PIO` -> 最后开启 `POE`，并保留非本任务位。
- [ ] 段码从逻辑段集合和当前 mapping 生成，没有固定端口假设。
- [ ] 扫描顺序为全关 -> 段码 -> 单位选 -> 延时 -> 全关。
- [ ] persistent display state 与所有 scratch 分区。
- [ ] 精确刷新时序通过 clock/cycle audit。
- [ ] 静态检查和 `builtin_compiler` 目标编译 0 error / 0 warning，`release` 返回 `RELEASED`。

### 后续硬件验收（仅用户明确要求时）

- [ ] ASM 已烧录到目标板，镜像 hash 与 release 证据一致。
- [ ] 实板逐段逐位映射与已确认 board profile 一致。
- [ ] 使用示波器或逻辑分析仪记录位选、段线和 frame period。
- [ ] 全数字、DP、刷新、亮度和电流通过验收。
